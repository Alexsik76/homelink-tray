# HomeLink

[![CI](https://github.com/Alexsik76/homelink-tray/actions/workflows/ci.yml/badge.svg)](https://github.com/Alexsik76/homelink-tray/actions/workflows/ci.yml) [![Release](https://img.shields.io/github/v/release/Alexsik76/homelink-tray?include_prereleases)](https://github.com/Alexsik76/homelink-tray/releases)

[English](README.md)

Програма для системного лотка Windows, яка відкриває доступ до віддалених ПК: підіймає
тунелі WireGuard, будить ПК (через вузол-посередник по SSH, магічним пакетом або командою),
присипляє й вимикає їх через SSH, відкриває віддалений робочий стіл і показує стан кожного
тунелю й ПК біля лотка.

Версія 1.0 написана на Rust з інтерфейсом [Slint](https://slint.dev) і перебуває в розробці
(кандидати у випуск публікуються як попередні випуски). Випущену версію 0.3.0 на Python
перенесено до архіву [`legacy/python`](legacy/python/README.uk.md).

## Як це працює

- **Панель.** Лівий клік по значку в лотку відкриває панель: тунелі ліворуч, навпроти кожного —
  ПК за ним, ПК без тунелю — останніми. Кожен елемент — назва й позначка стану (зелена: працює,
  жовта: у процесі, синя: вимкнено, сіра рамка: невідомо, червона: остання дія завершилася
  збоєм). Лівий клік відкриває дії, правий — вікно відомостей. Сон і вимкнення потребують
  другого натискання.
- **Значок у лотку.** Екран монітора показує загальний стан ПК, квадрат у куті — стан тунелів;
  підказка значка — скільки тунелів піднято і скільки ПК у мережі.
- **Тунель** вважається робочим, коли його сервер дає рукостискання WireGuard (або, якщо
  вказано вузол перевірки, коли той відповідає на ping).
- **Пробудження.** Для ПК за тунелем «Розбудити» спершу піднімає тунель. Програма ніколи не
  відключає тунель сама: лише кнопкою тунелю. ПК вважається увімкненим, коли всі його порти
  готовності приймають з'єднання TCP.
- **Сповіщення** в лотку: ПК прокинувся, тунель чи ПК зник, будь-яка дія не вдалася.
- **Налаштування** у файлі `config.toml` поруч із програмою, а також вікно налаштувань, майстер
  додавання ПК із п'яти кроків, сторінка довідки й сторінка «Можливості системи», що показує,
  які програми знайдено (клієнт WireGuard, OpenSSH, `mstsc`…); дія, для якої бракує програми,
  неактивна й пояснює чому. Під час збереження змінюються лише змінені
  значення, тож коментарі лишаються.
- Світла й темна теми, англійська та українська мови.

**Жодних секретів і жодного HTTP.** До посередників і ПК програма звертається системним
клієнтом OpenSSH за ключем. HomeLink не зберігає паролів, не надсилає телеметрії, не перевіряє
оновлень і з'єднується лише з вузлами з налаштувань. CI не пропускає збірку, у яку потрапила
бібліотека клієнта HTTP чи TLS.

## Вимоги

- Windows 10 (зокрема LTSC) або 11, права адміністратора (тунель працює як служба Windows;
  програма запитує права під час запуску).
- Офіційний [клієнт WireGuard](https://www.wireguard.com/install/), у який кожен тунель
  один раз імпортовано.
- Клієнт OpenSSH (Параметри > Програми > Додаткові компоненти > Клієнт OpenSSH; на Windows 10
  LTSC його може не бути) — для посередників, сну й вимкнення.
- Для пробудження через посередника: маршрутизатор MikroTik з RouterOS 7 або вузол Linux з
  `etherwake` чи `wakeonlan` у мережі ПК.
- Для сну й вимкнення через SSH: сервер OpenSSH на ПК (Linux або Windows з обліковим записом
  адміністратора).

## Початок роботи

1. Завантажте `HomeLink.exe` зі сторінки [випусків](https://github.com/Alexsik76/homelink-tray/releases)
   і покладіть в окрему теку. Виконуваний файл не має цифрового підпису, тому під час першого
   запуску Windows SmartScreen може показати попередження.
2. Запустіть його. Під час першого запуску програма створює поруч із собою `config.toml` за
   шаблоном із коментарями ([`rust/app/config.example.toml`](rust/app/config.example.toml)) і
   завершується.
3. Запустіть знову. Тунель, посередник і ПК у шаблоні — приклади: у вікні налаштувань (кнопка
   внизу панелі) змініть або видаліть їх, додайте тунелі формою тунелю (виберіть один із
   тунелів, імпортованих у клієнт WireGuard), а ПК — майстром.
   Майстер створює ключі SSH, показує команди для посередника й ПК, перевіряє з'єднання й
   питає дозволу, перш ніж довіряти ключу вузла. `config.toml` можна редагувати й вручну.

Параметри командного рядка:

| Параметр | Значення |
| --- | --- |
| `--config <шлях>` | Інший файл налаштувань |
| `--lang auto\|en\|uk` | Мова замість указаної в налаштуваннях |
| `--theme auto\|light\|dark` | Кольори панелі (типово — тема застосунків Windows) |
| `--check-config` | Перевірити файл налаштувань, показати всі помилки й завершитися |
| `--version` | Показати версію й завершитися |

### Автозапуск без запиту UAC

У PowerShell з правами адміністратора:

```
schtasks /create /tn HomeLink /tr "C:\path\to\HomeLink.exe" /sc onlogon /rl highest /f
```

## Пробудження через посередника

Магічний пакет має бути надісланий усередині мережі ПК: широкомовний кадр не проходить через
маршрутизований тунель. HomeLink підключається до посередника через SSH і виконує там одну
команду:

| Набір | Команда на посереднику |
| --- | --- |
| `routeros` | `/tool wol mac=<MAC> interface=<інтерфейс>` |
| `etherwake` | `[sudo -n ]etherwake -i <інтерфейс> <MAC>` |
| `wakeonlan` | `[sudo -n ]wakeonlan [-i <адреса>] <MAC>` |

Майстер показує команди для підготовки посередника: на RouterOS — група, якій дозволено лише
вхід через SSH і `/tool wol`, користувач у ній, обмежений адресою цього комп'ютера, і відкритий
ключ; на Linux — пакет, ключ в `authorized_keys` і, якщо потрібен `sudo`, правило в
`sudoers.d` для цієї однієї програми. Ключу вузла довіряють у майстрі після порівняння відбитка.

Без посередника магічний пакет можна надіслати з цього комп'ютера на власну IP-адресу ПК;
тоді маршрутизатору перед ПК потрібен статичний запис ARP для неї (майстер це пояснює).

## Сон і вимкнення через SSH

HomeLink надсилає готову команду: на Linux `sudo systemctl suspend -i` або
`sudo systemctl poweroff`, на Windows `rundll32.exe powrprof.dll,SetSuspendState 0,1,0`
(за ввімкненої гібернації ПК переходить у неї) або `shutdown /s /t 0`. Крок 4 майстра показує,
що один раз виконати на ПК:

- **Linux** (від імені root): відкритий ключ в `authorized_keys` користувача і
  `/etc/sudoers.d/homelink`, що дозволяє йому виконувати без пароля рівно ці дві команди. `-i`
  присипляє ПК навіть тоді, коли щось блокує сон (GNOME блокує його, поки існує сеанс
  віддаленого робочого стола).
- **Windows** (PowerShell від імені адміністратора): сервер OpenSSH, запущений зараз і під час
  завантаження, і ключ в `administrators_authorized_keys`, доступному лише адміністраторам і
  SYSTEM.

## Віддалений робочий стіл

Кнопка RDP під час першого використання записує `rdp\<id ПК>.rdp` поруч із налаштуваннями й
відкриває його в `mstsc`; файл більше не перезаписується, тож його можна підписати. Паролем
HomeLink не займається: введіть його у вікні віддаленого робочого стола або збережіть командою
`cmdkey /generic:TERMSRV/<адреса ПК> /user:<користувач> /pass`.

## Файли поруч із `config.toml`

`homelink.log` (до 1 МБ, дві попередні копії, місцевий час), `homelink.lock` (не дає запустити
другу копію), `keys\` (ключі SSH, створені майстром) і `rdp\` (файли віддаленого робочого стола).

## Збирання й розробка

Версію Rust закріплено в [`rust/rust-toolchain.toml`](rust/rust-toolchain.toml). Застосунок
працює на Windows; ядро (`rust/core`) і його тести — також на Linux.

```
cd rust
cargo test --workspace --all-features
cargo build -p homelink --release              # збірка для випуску
```

На Linux застосунок можна перевірити для Windows командою
`HOMELINK_NO_RESOURCES=1 cargo clippy -p homelink --all-features --target x86_64-pc-windows-msvc`
(змінна пропускає ресурси Windows, яким потрібен `rc.exe`).

Документи (англійською): [архітектура](docs/rust-architecture.md),
[інтерфейс](docs/design/ui-handoff.md) і його [темна тема](docs/design/ui-handoff-dark.md);
[список ручної перевірки випуску](docs/release-checklist.uk.md) — українською.
