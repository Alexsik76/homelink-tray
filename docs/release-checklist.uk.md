# HomeLink 1.0: список ручної перевірки на Windows

Перевірка кандидата у випуск на справжньому комп'ютері: те, чого не можуть довести тести й CI.
Проходиться на Windows 11 (і, за змоги, на Windows 10 LTSC) перед кожним `v1.0.0-rc.N` і
перед `v1.0.0`.

**Як звітувати.** Для кожного пункту — `OK`, `ЗБІЙ` або `—` (не перевірялося) і коротка
примітка. Для кожного збою додайте `homelink.log` (лежить поруч із `config.toml`) і, якщо
йдеться про вигляд, знімок екрана. Найзручніше скопіювати таблицю в кінці файлу й заповнити її.

## 0. Підготовка

| # | Що зробити | Очікуваний результат |
| --- | --- | --- |
| 0.1 | Завантажте `HomeLink.exe` з попереднього випуску (`v1.0.0-rc.N`) і, окремо, артефакт `HomeLink-rust-demo` з останнього запуску CI гілки `main`. Звірте суму: `Get-FileHash HomeLink.exe` має збігатися з `HomeLink.exe.sha256` | Сума збігається |
| 0.2 | Створіть порожню теку, наприклад `C:\HomeLink-test`, і покладіть туди `HomeLink.exe` з випуску | — |
| 0.3 | У `cmd` виконайте `ssh -V` | Версія OpenSSH; якщо «не знайдено», встановіть Клієнт OpenSSH (Параметри > Програми > Додаткові компоненти) |
| 0.4 | Переконайтеся, що клієнт WireGuard установлено й тунель додому імпортовано (у WireGuard він неактивний) | — |

| D6 | «Додати ПК», крок 1: назва, адреса, порти (наприклад `22` або `3389`) | Неприпустимі значення підсвічуються з поясненням; «Далі» пропускає лише правильні |

| D9 | Скопіюйте команди й виконайте на роутері (замініть `<address of this computer>` на адресу цього комп'ютера в мережі роутера) | Команди виконуються без помилок; `/user print where name=homelink` показує користувача з `address=…/32`, `/user ssh-keys print` — його ключ |

## E. Дії з Linux-ПК

| # | Що зробити | Очікуваний результат |
| --- | --- | --- |
| E1 | Вимкніть ПК (або приспіть), тунель відключено. На ПК > «Розбудити» | Тунель підіймається, потім ПК жовтий (будиться), потім зелений; сповіщення «ПК у мережі» |
| E2 | «Сон» → «Так, у сон» | Перше натискання лише показує підтвердження; після «Так» ПК засинає, позначка синя; сповіщення «команду сну надіслано», але не «ПК втрачено» |
| E3 | «Розбудити» сплячий ПК | ПК прокидається, позначка зелена |
| E4 | «Вимкнути» → «Так, вимкнути» | ПК вимикається; позначка синя; без сповіщення «ПК втрачено» |
| E5 | Розбудіть, потім RDP | Відкривається `mstsc` з `rdp\<id>.rdp`; файл створено один раз (повторне RDP його не змінює); пароль вводиться в `mstsc` |
| E6 | Зупиніть `sshd` на ПК (`systemctl stop ssh`), натисніть «Сон» → «Так, у сон» | Сповіщення про помилку з зрозумілим текстом (з'єднання не вдалося), червона позначка; ПК не засинає. Запустіть `sshd` знову |
| E7 | Тимчасово змініть у посередника користувача на неіснуючий, «Розбудити» вимкнений ПК | Сповіщення «не вдалося розбудити» з причиною; червона позначка. Поверніть значення |
| E7b | Тимчасово вкажіть у ПК неіснуючий інтерфейс (наприклад `bridge-x`), «Розбудити» | Одразу сповіщення «не вдалося розбудити» з текстом RouterOS `input does not match any value of interface`; червона позначка. Поверніть значення |
| E8 | Вимкніть ПК кнопкою живлення (не через HomeLink) | Після кількох перевірок (`offline_after_failures`) — сповіщення «ПК втрачено», позначка синя |
